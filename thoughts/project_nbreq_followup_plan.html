NBReq Post-Release Follow-up Plan

Published baseline: nbreq 0.1.0  |  Original tracker: thoughts/project_nbreq_plan.html  |  Opened: 2026-08-25  |  Overall status: F0 accepted; F1 accepted

Purpose

This companion tracker governs work after the first HTTP release. It keeps the accepted 0.1.0 ownership and lifecycle model intact while exposing the already-proven Engine-owned DNS resolver and TCP reactor as useful public capabilities, then removes the wire-only Hickory dependency without changing observable resolver behaviour.

The original WP0–WP11 tracker remains the authoritative history of the HTTP product and release. This document begins a new programme so follow-up API decisions and evidence do not blur the boundary of the published release.

F1 acceptance is Windows plus exact-source Ubuntu/Linux. macOS/Darwin is planned and unverified; it is not covered by the word “Unix.” Portable reactor, DNS wire/state, HTTP, and TLS layers should avoid gratuitous macOS incompatibility, but DNS configuration discovery must not silently inherit Linux /etc/resolv.conf semantics on Darwin or other unverified Unix targets.

Starting point: native HTTP is the ordinary default; Engine uniquely owns networking, cancellation, wakeup, limits, metrics, worker services, and joined shutdown. DNS, TCP, HTTP/1.1, TLS, pooling, redirects, and streaming already run on that owner on Windows and Linux, with an old-Wine polling fallback. The follow-up exposes capabilities; it does not create another runtime.

2. Frozen Principles

  1. One Engine, three capabilities. HTTP Client, Resolver, and TcpConnector are issued tickets into one unique Engine lifecycle.
  2. No public constructors. Capability handles are cheap and cloneable, but they neither own nor extend Engine life. Detached handles reject new work with EngineStopped.
  3. No hidden runtime. Public DNS uses the existing resolver thread and public TCP uses the existing native reactor. They never construct parallel pollers or private Engines.
  4. HTTP selection is only HTTP selection. HttpBackend does not select DNS or TCP. With native support compiled, an Engine using an explicit HTTP backend may still issue native DNS/TCP handles; without native support, those operations fail Unsupported before admission.
  5. One terminal winner. Resolve and connect each have exactly one completed, failed, or cancelled terminal. Cancellation is idempotent after terminal state and fails closed across Engines.
  6. No user code on owners. Start callbacks use the accepted callback-dispatch domain and never run on the resolver or reactor thread or under internal locks.
  7. Manual means passive. Submit and try_* calls never drive. Blocking execute, wait, read, and send calls reject manual mode. Engine::drive advances HTTP, DNS, and TCP together.
  8. Bounds before growth. Names, result counts, commands, live operations, connections, and queued bytes are bounded before resource acquisition or buffer growth.
  9. Joined shutdown. Engine-wide cancellation and consuming shutdown cover HTTP requests, public resolutions, public connects, and live TCP streams. No thread or socket ownership escapes that join.
  10. One crate. Public interfaces remain in nbreq. Internal module/workspace reorganisation may remain invisible.

3. Public Contract Freeze

3.1 Resolver semantics

  • Resolver is a hostname-to-address service, not arbitrary DNS.
  • NXDOMAIN and NoData commit ResolveCompletion::Completed. SERVFAIL, REFUSED, malformed replies, truncation after bounded TCP retry, timeout, and no usable nameserver commit Failed.
  • DnsFailure is payload-free failure detail like TlsFailure. It does not encode NXDOMAIN or NoData, and timeout remains classified by TimeoutKind.
  • Names are exact ASCII/punycode at build time. No Unicode-to-IDNA conversion occurs silently.
  • Search suffix use is per-request opt-in. It is never an Engine-wide switch and cannot affect HTTP lookups.
  • Address family and order are explicit. The public defaults are AddressFamily::Both and AddressOrder::Ipv4ThenIpv6. Both collects A and AAAA rather than copying HTTP's A-first/AAAA-on-NoData fallback. Order within each family is preserved; combined IPv4/IPv6 ordering does not promise parallel queries or Happy Eyeballs. Both completes only when each required family reaches a semantic DNS terminal; a transport/protocol failure in either fails the operation rather than silently returning a partial set.
  • Use, Refresh, and Bypass are the complete initial cache modes. Cache validity is exposed as an in-process Option<Instant>, not a wall clock.
  • The resolver and HTTP share the existing Engine-owned DNS cache. A public Refresh can therefore replace an entry later observed by HTTP on that Engine; this visibility is deliberate and does not permit public search policy to affect HTTP.
  • Every request has a bounded result count at or below the Engine ceiling. Resolver validation and cache lookup cannot bypass admission or terminal accounting.

3.2 TCP connect semantics

  • A connect is a finite operation with start, submit, and spawned-mode execute. Its completed value is one unique live TcpConnection.
  • TcpConnectRequest accepts either a hostname plus port or a literal SocketAddr. A hostname connect charges public DNS and standalone TCP budgets; a literal skips DNS.
  • Hostname connect uses an exact name with no search-suffix expansion and the public resolver defaults: AddressFamily::Both, AddressOrder::Ipv4ThenIpv6, and CacheMode::Use. It tries addresses serially in that order until one connects; this is not Happy Eyeballs. NXDOMAIN or NoData fails the connect because no live address was produced. Any later per-connect DNS policy requires explicit builder options rather than silently inheriting HTTP's private fallback.
  • Connect timeout includes capacity waiting, DNS when required, and TCP connection establishment. The clock begins at admission and ends when the live connection is produced.
  • Optional connected-phase read_inactivity_timeout and write_inactivity_timeout govern the live object. Write inactivity runs only while accepted output is waiting for socket progress. Read inactivity pauses under consumer backpressure. Blocking connected operations reject manual mode rather than driving it.
  • The unsplit connection supports simple bidirectional use. split(self) returns unique reader and writer halves for concurrent ownership.
  • Connected reads and writes are bounded queue I/O with passive try_* operations. They do not create a second Completion protocol.
  • An unfinished writer drop aborts the connection. Split TcpWriter::finish(self) drains accepted output and then half-closes the write side. Unsplit TcpConnection::finish(&mut self) performs the same write-side operation without consuming the still-live reader.
  • A reader drop before observed EOF cancels the connection, including after writer finish. Reader drop after EOF is harmless.
  • Dropping an unsplit connection before its writer has finished and its reader has observed EOF aborts it. Dropping it after both directions are terminal is harmless.
  • The reader drains retained bytes before reporting EOF. Reset, cancellation, Engine stop, and local fail-closed drop wake blocked readers and writers promptly.
  • TCP is cleartext. There is no into_std, raw descriptor, escaped socket, or hidden TLS mode.

3.3 Shared budgets

  • HTTP pool capacity, public DNS inflight capacity, and standalone TCP capacity are distinct anti-starvation budgets.
  • max_connections and max_connections_per_origin remain HTTP-only. max_standalone_tcp_connections independently bounds pending and live standalone TCP. OS/process resource limits may cap their sum, but standalone TCP occupancy does not consume or shrink the configured HTTP pool.
  • An Engine-wide queued-byte ceiling will cover HTTP upload/unread-response queues plus standalone TCP send/unread-receive queues once F2 can charge max_queued_bytes atomically. F0 does not publish that field. HTTP streaming keeps max_stream_queued_bytes.
  • Per-operation and per-connection windows may request less than their Engine limit, never more.
  • HTTP-internal DNS remains reserved from public-resolver exhaustion. A hostname connect reserves its standalone TCP permit for the lifetime of the accepted connect/live connection and borrows one public-DNS permit only while resolving. The DNS permit is released before socket establishment; the connect retains one ID and one canonical terminal throughout.
  • Engine::cancel_all covers HTTP, public DNS, pending connects, and live standalone TCP. The callback-event budget is shared by callback-bearing HTTP, resolve, and connect terminals; connected queue I/O does not invent callbacks.
  • Metrics remain payload-free and distinguish HTTP, public DNS, and standalone TCP current/high-water/cumulative activity.

4. Proposed API Shape

F0 compiled the consumer shape below. Operations currently return Unsupported before admission; they are not connected to the private resolver or reactor.

let engine = Engine::new(config)?;

let http = engine.client();
let resolver = engine.resolver();
let tcp = engine.tcp_connector();

4.1 Resolution

let request = ResolveRequest::hostname("example.com")
    .address_family(AddressFamily::Both)
    .address_order(AddressOrder::Ipv4ThenIpv6)
    .cache_mode(CacheMode::Use)
    .max_results(8)
    .total_timeout(Duration::from_secs(5))
    .build()?;

let response = resolver.execute(request)?;
match response.status() {
    ResolveStatus::Answer => { /* use response.addresses() */ }
    ResolveStatus::NameNotFound | ResolveStatus::NoData => { /* valid negative answer */ }
}

Compiled public family: Resolver, ResolveRequest/ResolveRequestBuilder, PendingResolve, ResolveHandle, ResolveCompletion, ResolveResponse, ResolveStatus, ResolvedAddress, AddressFamily, AddressOrder, CacheMode, DnsFailure, and ResolveWaitOutcome.

4.2 TCP

let request = TcpConnectRequest::hostname("example.com", 1234)
    .connect_timeout(Duration::from_secs(5))
    .build()?;

let connection = tcp.execute(request)?;
let handle = connection.handle();

// Simple callers may read/send on `connection` directly.
// Concurrent callers may consume it into unique halves:
let (mut reader, mut writer) = connection.split();
writer.send(bytes)?;
writer.finish()?;
while let Some(count) = reader.read(&mut buffer)? {
    consume(&buffer[..count]);
}

Compiled public family: TcpConnector, TcpConnectRequest/TcpConnectRequestBuilder, TcpConnectTarget, PendingTcpConnect, TcpConnectHandle, TcpConnectCompletion, TcpConnectWaitOutcome, TcpConnection, TcpConnectionHandle, TcpReader, TcpWriter, TcpRead, TcpStreamError, TcpSendError/TcpSendErrorKind, and TcpFinishError.

Existing vocabulary wins: finite resolve/connect operations mirror HTTP start, submit, execute, RequestId, ExecuteError, and cloneable cancellation handles. Live TCP queue I/O mirrors the ownership lessons of ResponseReader and UploadSender, but it is not called submit_stream and does not adapt HTTP Completion.

F1-R1 design (accepted FQ-10, implemented in the working tree): public search is an NBReq policy that reads platform suffix lists and then applies one frozen candidate algorithm. It must not clone glibc ndots, Windows DNS devolution, systemd-resolved internals, NetBIOS, LLMNR, or mDNS.

Implemented discovery: native_dns_config snapshots nameservers, bounded suffixes, attempt timeout, and attempts at Engine construction. Windows ranks up-adapters by metric then adapter/server order via ipconfig 0.3.4. Suffixes follow SearchList-first, ranked-adapter fallback, computer-Domain-last, with no devolution: a filtered computer SearchList from HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters is complete when non-empty; otherwise adapter Domain falling back to DhcpDomain from HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{adapter_name} in that same rank, then computer Domain from the computer Parameters key. Registry strings are read through pinned windows-registry 0.6.1. Linux takes the last search or domain directive from /etc/resolv.conf and ignores ndots. Ordinary macOS discovery fails Unsupported without reading /etc/resolv.conf; other unverified Unix targets fail closed the same way. Injected nameserver and suffix fixtures remain usable on every target. HTTP Command::Resolve still queries the origin host as a single exact name. Public cache keys remain the queried candidate Name. ResolveResponse::name() is the request identity; candidate_name() is Answer-only.

What must not be cloned

  • glibc/musl/k8s ndots (defaults differ; Kubernetes often uses 5).
  • Windows suffix devolution (host.corp.example.com leaking to host.com).
  • glibc glibc_normalize caps (3 nameservers / 6 suffixes) as hidden discovery rules. Nameserver selection stays as today; suffix count is an explicit NBReq bound.
  • Hostname-derived domain fallback (get_system_domain).
  • Special-casing .local, LLMNR, NetBIOS, multicast DNS, or NRPT.
  • Live re-read of OS config after Engine construction.

Proposed candidate algorithm

  • Trailing-dot absolute names: one candidate, the normalized identity. The search flag is recorded but expansion does not apply. Unchanged from F0.
  • Search not requested, or HTTP, or hostname TCP: one exact candidate. HTTP never consults the suffix list.
  • Relative name with search requested and no dot in the identity: suffixes only, in snapshot order. If the filtered suffix list is empty, fall back to the exact identity so the flag is not a silent no-op that then fails closed.
  • Relative name with search requested and at least one dot: exact identity first, then each identity.suffix.
  • Dedup: normalize suffixes as DNS names (lowercase ASCII, strip one trailing dot, same label rules as public names). Drop invalid, empty, and root suffixes. Drop later duplicates case-insensitively. Drop a generated candidate that equals an earlier candidate. Skip concatenations that exceed 253 octets or produce an invalid label; do not fail the operation for a single oversized suffix.
  • Bounds: at most 6 suffixes after filtering (MAXDNSRCH-shaped, but ours). At most 7 candidates. One public inflight permit and one RequestId cover the whole sequence. Existing per-candidate CNAME hop budget and UDP/TCP fallback are unchanged. The request total deadline covers every candidate.

Continuation, failure, and final status

  • Each candidate runs the existing public family policy to a semantic terminal (Ipv4 / Ipv6 / Both). Both still fails the whole operation if either required family has an operational/protocol failure.
  • Answer stops the search and is the Completed result.
  • NXDOMAIN and NoData both continue to the next candidate. Search is address-hunting; a NoData on an unqualified or partially-qualified name must not hide a later suffix hit. This deliberately differs from stubs that treat NODATA as definitive.
  • Operational failure (SERVFAIL, REFUSED, malformed, truncated-after-TCP, timeout, I/O, protocol) fails the operation immediately. Do not try the next suffix to paper over an outage.
  • Cancel / Engine stop / expired total deadline fail or cancel the whole search. Do not promote an earlier negative to Completed.
  • Exhaustion: NameNotFound if every candidate was NXDOMAIN; NoData if at least one candidate was NoData and none was Answer.
  • ResolveResponse::name() stays the request identity. Do not add a winning-name field in this remainder.

Caching

  • Cache keys remain the queried candidate Name (family map plus HTTP name-level view), never the relative request string.
  • A search for www that answers as www.corp.test may populate HTTP’s view of www.corp.test. It must not populate a www entry that HTTP or exact public lookup would then consume.
  • IPv6-only public completions update the public AAAA family cache but never mutate HTTP’s coherent A-first name-level cache view. IPv4 and Both may publish that view.
  • Use consults each candidate’s cache in order (cached NXDOMAIN/NoData continue; cached Answer wins). from_cache stays false once any candidate required the network and never returns to true. Refresh skips reads and still writes the candidates actually queried. Bypass neither reads nor writes.
  • from_cache is true only when the entire search required no network traffic. A cached NXDOMAIN/NoData followed by a network Answer is not from cache. Exact lookups are a one-candidate search.
  • An exhausted negative’s valid_until is the earliest validity across every candidate needed to prove exhaustion, or None if any contributing negative lacks cache validity.
  • ResolveResponse::candidate_name() is Option<&str> populated only for Answer. It is the expanded question name that supplied addresses, not a CNAME canonical target. Exact lookups return the same identity as name(). Exhausted negatives return None.

Platform snapshot

  • Linux: last search or domain directive from /etc/resolv.conf (get_last_search_or_domain). Ignore ndots, rotate, lookup, and hostname-derived domain. This path is target_os = "linux" only.
  • macOS / other Unix: ordinary system discovery fails ErrorKind::Unsupported. Darwin must not inherit Linux stub semantics. Linux/Windows helper tests assert the fail-closed error constructors; the target-selected macos_ordinary_system_discovery_is_unsupported test remains for F6/on-Mac execution. System Configuration and scoped/supplemental routing are F6, not F1. No macOS support claim is made.
  • Windows: if the computer SearchList at HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters is non-empty after filtering, that list is complete (admin “append these suffixes in order”). Otherwise collect adapter Domain, falling back to DhcpDomain, from up adapters in the same metric/adapter ranking already used for nameservers, reading HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{adapter_name} through pinned windows-registry 0.6.1, then append computer Domain from the computer Parameters key if missing. Nameservers still come from ipconfig 0.3.4. No devolution.
  • Suffixes are snapshotted with nameservers at Engine construction. Tests inject a suffix list beside the injected nameserver so Windows and Ubuntu run identical QNAME-order fixtures.

  • Continue realistic Windows/Linux/Wine interruption, restart, and multi-hour lifecycle runs while retaining HTTP rollback during early observation.
  • Profile bulk body-span decoding, owned-chunk movement, bounded fixed-body growth, rustls batching, request maps/serialization, whole-process memory, and idle CPU.
  • Prefer removal of unreasonable retention and fixed cost over synthetic throughput ranking.
  • Do not weaken memory ceilings, framing, lost-wake recovery, cancellation, contamination safety, or joined shutdown for performance.

F6 — macOS/Darwin platform honesty

After F1–F5; not an F1 blocker

macOS is planned and unverified. It is not covered by “Unix,” and F1 acceptance remains Windows plus exact-source Ubuntu/Linux. Portable reactor, DNS wire/state, HTTP, and TLS work should avoid gratuitous Darwin incompatibility, but ordinary system DNS discovery currently fails closed rather than reading Linux /etc/resolv.conf. Linux/Windows helper tests verify that fail-closed error contract; the target-selected macOS discovery test is reserved for F6/on-Mac execution. No macOS support claim is made.

  • Investigate System Configuration and scoped/supplemental resolver routing rather than flattening everything into one global nameserver list.
  • Do not clone glibc ndots, Windows devolution, or a single stub resolv.conf as Darwin policy.
  • The initial physical gate may use the available Intel Mac. Apple Silicon may initially receive CI compile coverage only. Neither architecture is promised until its applicable gate passes.
  • Provisional gate: full build/tests/clippy/doctests; Mio/kqueue wake, cancel, and joined shutdown; local UDP/TCP DNS fixtures; HTTP cleartext and TLS; verified Keychain TLS; ordinary system DNS discovery; a scoped/split-DNS experiment; repeated Engine lifecycle; and a longer run.

Acceptance: Darwin resolver discovery is truthful for the claimed architecture, injected fixtures still cover protocol/state independently of OS discovery, and no F1/F2/F3 behaviour is rewritten to make macOS pass.

FQ-01Does obtaining an unavailable capability fail, or does its first operation fail?Engine::resolver() and tcp_connector() issue ordinary tickets; unavailable operations fail Unsupported before ID, permit, or queue acquisition. This keeps issuance cheap and feature-invariant.Accepted for F0
FQ-02What does an optional trailing dot mean?Accept zero or one terminal dot as an explicit absolute spelling; normalize cache/question identity to lowercase ASCII without the terminal dot, and retain the absolute bit so execution can suppress search-suffix expansion even when use_search_suffixes(true) is requested. FQ-03How do cache modes behave?Use: read and populate. Refresh: skip cache read and replace from the network. Bypass: neither read nor populate. Negative cache entries follow the same mode and expose honest validity.Accepted for F0
FQ-04What are the default address family and combined-family order?Default to AddressFamily::Both and AddressOrder::Ipv4ThenIpv6. FQ-05How are blocking TCP queue operations named?Use ownership-explicit try_send(Vec<u8>)/send(Vec<u8>), returning the unaccepted suffix on refusal. Consider borrowed Read/Write adapters only later.Accepted for F0
FQ-06Does a connect total timeout continue after connection?No. Resolve/connect terminal clocks end when the live object is produced. Optional read/write inactivity policies govern the connected phase and pause under consumer backpressure where progress is impossible.Accepted for F0
FQ-07Does a combined-family lookup mean fallback or collection?Call the public variant AddressFamily::Both: collect A and AAAA and order the combined result explicitly. FQ-08How does manual drive_until support three terminal types?Make Engine::drive_until generic over a tiny sealed waiter-target trait with an associated output. FQ-09What happens when the unsplit connection is dropped?Drop before writer finish plus reader EOF aborts; drop after both directions are terminal is harmless. Splitting transfers the same rule to the two unique halves.Accepted for F0
FQ-10What is public search-suffix expansion?Per-request opt-in only. Snapshot OS suffixes at Engine construction, then apply a frozen NBReq candidate algorithm: trailing-dot is exact-only; undotted names try suffixes and skip bare exact when any suffix exists; dotted relative names try exact first. Continue on NXDOMAIN and NoData; fail closed on operational errors. Cache by queried candidate, never by the relative request name. from_cache is true only when the entire search required no network. Exhausted-negative valid_until is the earliest contributing validity, or None. candidate_name() is Option<&str> for Answer only (expanded question, not CNAME target). HTTP and hostname TCP never expand. Ignore OS ndots and Windows devolution.Accepted for F1-R1
