GDS Rust DPWebRPC Production Readiness

Component: gds/rust/gds/src/dplib/dpwebrpc.rs  |  Delphi bridge: lib/DPWebRPC.pas  |  Initial review: 2026-08-15  |  Overall status: not ready for unrestricted production

Purpose

This is the working tracker for taking the Rust DPWebRPC implementation from preview use to full production. It records the production-readiness review, implementation order, acceptance criteria, verification evidence, rollout gates, and decisions that future sessions must preserve.

The scope includes the Rust poller and response sender, the shared Rust HTTP client where it directly affects DPWebRPC, the Rust/Delphi FFI boundary, the Delphi TDPWebRPC lifecycle wrapper, and compatibility with the deployed gateway protocol.

Production gate: do not turn on Rust DPWebRPC universally, and do not remove the Delphi fallback until delivery failure, queue pressure, malformed traffic, and poller-panic recovery have been exercised under fault injection. Lifecycle stop no longer joins a mid-GET poller on the VCL thread. TLS verification is a separate project (Wine dual-named host); it remains mandatory before any HTTPS rollout.

1. Current State and Evidence

What is working

  • The Rust implementation polls the gateway on a dedicated thread, decrypts and queues incoming requests, and returns them to Delphi through a timer-driven FFI drain.
  • Responses are encrypted and posted through a four-worker Rust thread pool with up to five attempts for transport errors.
  • The implementation is gated by use_rust_webrpc, Data.DisableRust, and Options.DisablePreviewFeatures, so a practical rollback path already exists.
  • The focused Rust suite passed on 2026-08-15: 56 passed, 0 failed, including parser hardening, panic-park, and poller restart.
  • Retained local logs contained 48 Rust poller starts and 444 successful POST records, with no retained decrypt/base64 or retry-exhaustion errors. This is useful operational evidence, but it is not a substitute for load and fault testing because the logs rotate.
Protocol tests now include OpenSSL PKCS7 golden vectors, a PHP leftover-pad fixture, poll-body trim, Drop-returns-quickly, GET lease, successor handoff, checked headers, and poller panic restart. They still do not cover bounded queues during a prolonged outage or Delphi-visible health. Do not check captured customer payloads into the tree.

2. Prioritized Findings

IDPriorityFindingImpactStatus
DWR-01 Deferred TLS certificate and signature verification are disabled. UreqDpHttpClient::new always uses build_insecure_agent, whose verifier accepts every certificate and TLS signature. Kept this way after a Wine compatibility fight with a dual-named host. Any HTTPS DPWebRPC connection is vulnerable to transparent interception or modification. The legacy inner AES-CBC format does not restore message authenticity. Latent on today’s CAT port-80 / HTTP default. Treat as a separate project before any https:// rollout. Separate project
DWR-02 Was blocker The Delphi Rust lifecycle is not safe or idempotent. SetActive is a no-op when already in the requested state; Rust create happens before FActive and the drain timer; stop clears the handle then frees; Destroy tears down an active instance. FFI create/free/fetch/respond catch panics. Drop no longer joins the poller on the VCL thread (WP6). Watchdog reset and empty backup host should no longer leak, double-free, nil-deref the timer, or freeze the UI on Active := False. In code
DWR-03 High Responding is fire-and-forget. Rust reports success as soon as a POST job is queued. Non-OK bodies and exhausted retries are only logged, and Delphi ignores the FFI return code. GDS can lose a response while believing it completed the request. The remote web/mobile caller may hang or time out with no actionable GDS health state. Open
DWR-04 High Inbound and outbound queues are unbounded. Inbound uses Mutex<Vec<...>> and removes index zero; the thread pool uses an unbounded job channel; Delphi drains all pending messages in one timer event. A slow consumer or gateway outage can grow memory without limit, produce stale responses, make shutdown very long, and monopolize the Delphi main thread. Open
DWR-05 High Malformed decrypted frames can panic the only poller. Header parsing now requires an ASCII alphabetic type and an unsigned positive decimal sequence (no sign, no leading zeros, 1..=i32::MAX). Empty, non-ASCII, unknown-type, invalid-sequence, and bad-batch frames return a structured error and do not count as healthy communication. A valid batch prefix is salvaged when a later item is malformed, because the broker already dequeued the batch. The poller supervisor catch_unwinds: park inbound calls while still holding the GET lease, release the lease, mark unhealthy, then restart with capped exponential backoff that resets after a successful poll. A bad frame logs and continues. A panic no longer kills polling or drops already-queued calls. Delphi still does not receive an explicit unhealthy FFI signal (WP8). In code
DWR-06 High Shutdown must not block the Delphi UI thread. Drop sets a shared cancellation flag, stops accepting POSTs, interrupts poll/POST backoff sleeps, and joins the poller plus POST pool on a background waiter. ureq cannot cancel an in-flight GET. Pollers for the same URL take a lease so a successor cannot GET until the previous poller exits. Remaining inbound RPC items are parked for that successor; this instance has no Delphi consumer after free. Alive ticks are not parked. If Rust stays off, a parked call is stale until the next Rust start (or is never consumed, same as switching to the Delphi poller which cannot see the Rust queue). Watchdog reset and application shutdown return immediately from dpwebrpc_free. Rapid restart does not steal the next broker GET. An in-flight GET after free is not delivered to the dying handle. In code
DWR-07 High No application-level payload limits are enforced. HTTP bodies, decoded ciphertext, plaintext, fields, batches, and queued requests can allocate based on remote input. A faulty or hostile endpoint can cause excessive memory/CPU use. Multiple clones during decode and batch processing amplify large responses. Open
DWR-08 High Full plaintext responses are logged, normally twice. Rust logs the complete response before encryption and Delphi logs it again after the FFI call. Logs can contain session material and sensitive operational/client data. Large site/API responses also create avoidable allocations, log locking, disk traffic, and oversized rotated files. Open
DWR-09 High Live CAT encrypts PKCS7; PHP decrypt dual-unpads in tracked templates. send_text stays openssl_encrypt(..., flags=0) (Delphi poll decrypt is C-string and already tolerates leftover PKCS7 after |). import_text still uses OPENSSL_ZERO_PADDING, then webrpc_unpad: strip PKCS7 if valid, else rtrim NULs so Delphi zero-pad POSTs keep working. Source of truth: gds/install/cat/. The live gateway_server tree stays gitignored. The Delphi IV property is still not passed through the FFI. A PKCS7-only openssl_decrypt would reject Delphi ciphertext. Dual unpad keeps one input.php for both clients. Isolation-deployed on the first test CAT host; fleet copy still needed. Tracked + isolation host
DWR-10 High The legacy encryption is unauthenticated. AES-CBC uses a fixed IV and a key truncated/zero-padded to 16 bytes, with no MAC or authenticated envelope. Ciphertext is deterministic for matching prefixes and malleable. Correct TLS is therefore essential until a versioned authenticated protocol replaces it. Protocol migration
DWR-11 Medium An empty host fails open to a hard-coded HTTP test endpoint. A configuration or caller error can direct production data to an unintended cleartext test URL instead of refusing to start. Open
DWR-12 Medium Retry timing uses wall-clock time and fixed intervals. There is no exponential backoff or jitter. Clock rollback can produce a very long sleep, while a shared outage can synchronize many GDS installations into a retry surge. Open
DWR-13 Medium Operational state is mostly visible only in text logs. Delphi receives periodic successful alive events but not queue age, delivery failure, malformed-frame counts, or explicit poller death. Failures are detected late and are difficult to distinguish from endpoint, network, queue, or parser problems. Open

3. Implementation Work Packages

WP1 — Secure and validate construction

TLS deferred (Wine dual-named host; separate project). Empty-host fallback and FFI create Open. Addresses DWR-01 and DWR-11.

  • TLS certificate verification is deferred. Do not enable it as part of the current CAT HTTP canary. Revisit before any https:// host, with an explicit insecure opt-in if Wine still cannot verify the dual-named certificate.
  • Validate host, scheme, port, poll path, post path, and key before starting any thread.
  • Remove the hard-coded empty-host fallback. Return a structured construction failure instead.
  • Change the FFI create boundary to return failure without unwinding across extern "C".

Acceptance (when TLS is revisited): valid public certificates succeed; wrong hostname, expired certificate, unknown CA fail closed. Acceptance now: empty host and invalid port fail closed with a visible but non-secret error.

WP2 — Make the Delphi/Rust lifecycle safe

In code Addresses DWR-02. Shutdown duration is WP6 (also in code).

  • Done: SetActive no-op when already in the requested state; design-time sets the flag only.
  • Done: dpwebrpc_create must succeed before FActive or enabling the drain timer. Nil create leaves inactive so a later True can retry.
  • Done: stop disables the timer, moves the handle aside, clears the field, frees only a non-nil pointer.
  • Done: destructor stops an active instance; StopRust is safe if never started.
  • Done: catch_unwind on create (nil), free, fetch (null), respond (-2).
  • Done: bounded non-blocking shutdown (WP6). Active := False does not join a mid-GET poller on the VCL thread.

Acceptance: repeated true/false assignments, false-before-first-start, empty backup configuration, failed construction, refresh while active, watchdog reset, and destruction while active all complete without access violation, leak, double-free, or VCL freeze. A successor poller waits for the previous GET lease instead of overlapping.

WP3 — Replace fire-and-forget response delivery

Open Addresses DWR-03 and the outbound side of DWR-04.

  • Choose and document the contract: queued, accepted by HTTP, accepted by gateway/broker, or durably retained for retry.
  • Use a bounded outbound queue with sequence, enqueue time, attempt count, next-attempt time, and deadline.
  • Report terminal delivery failure to Delphi and system status rather than only logging it.
  • Classify failures: retry transient transport/5xx conditions; do not blindly retry permanent 4xx/protocol errors.
  • Treat a timeout after a possible server commit as ambiguous. Verify or define gateway deduplication by sequence before claiming exactly-once delivery.
  • Review the checked-in gateway behavior that returns OK even after broker forwarding errors.

Acceptance: tests cover connection refusal, timeout before send, timeout after gateway acceptance, non-OK 2xx body, 4xx, 5xx, broker rejection, process shutdown with pending work, and queue-full behavior.

WP4 — Bound inbound work and protect the Delphi main thread

Open Addresses inbound DWR-04 and DWR-07.

  • Use VecDeque or a bounded channel for inbound requests.
  • Set explicit maximum response bytes, decoded bytes, fields, field bytes, batch items, and queued requests.
  • Avoid cloning the entire message/list for each nested batch operation.
  • Drain a bounded count or bounded elapsed-time budget per Delphi timer event, then yield to the UI.
  • Define what happens when the queue is full. Prefer pausing polling/backpressure over silently dropping an already-dequeued broker request.
  • The process-wide inbound handoff map is unbounded and never expires. Bound it, key-expire stale parks, and treat it as the same class of queue-pressure risk as the live inbound queue.

Acceptance: sustained traffic above consumer capacity remains within configured memory bounds, keeps the UI responsive, and produces an explicit health state without silently losing requests.

WP5 — Harden protocol parsing and poller supervision

In code Addresses DWR-05 and part of DWR-13.

  • Done: parse_frame_header — ASCII alphabetic type plus unsigned positive decimal sequence (digits only, no sign, no leading zeros, 1..=i32::MAX). Empty, non-ASCII, missing/invalid sequence, unknown type, bad batch length, and trailing batch data return structured errors.
  • Done: inbound queue locks use poison recovery so a malformed frame cannot stick the mutex.
  • Done: malformed HTTP 200 bodies (bad base64/decrypt/UTF-8/headers) do not set comm_ok and do not emit alive ticks.
  • Done: a valid batch prefix is enqueued even when a later item is malformed. That is an explicit protocol decision: the broker already dequeued the batch, so salvaging accepted calls is preferred over dropping work that will not be redelivered.
  • Done: panic order is contain, park queued calls while still owning the GET lease, release the lease, mark the poller unhealthy, then restart with interruptible backoff (1s, doubling, cap 30s). Backoff is skipped on shutdown. A later successful poll clears unhealthy and resets restart backoff to 1s.
  • Remaining for WP8: expose unhealthy / malformed / panic counts to Delphi system status.

Acceptance: empty/multi-byte/unknown headers and bad batches error without panic. Zero, signed, and overflowing sequences are rejected. test_poller_restarts_after_panic, test_poller_restart_backoff_resets_after_recovery, and test_panic_parks_queued_call_for_successor cover supervision. A panic while the lease is held does not drop already-queued inbound calls or leave the lease stuck.

WP6 — Make cancellation and shutdown bounded

In code Addresses DWR-06.

  • Done: shared AtomicBool observed by the poller, outbound workers, and retry waits.
  • Done: stop accepting new outbound work before beginning shutdown.
  • Done: poll and POST backoff waits are interruptible (50ms slices on the real sleeper; mock sleep still records the full duration).
  • Done: ureq cannot cancel an in-flight request. Drop does not join on the caller; a dpwebrpc-shutdown thread joins the poller and POST pool. Drop logs its own return time; the waiter logs join duration.
  • Done: one GET lease per poll URL. A successor waits in the poller thread until the previous poller exits, so it cannot steal the next broker request.
  • Done: inbound RPC items still on a dying instance are parked for a successor with the same poll URL. Adoption happens only after the successor holds the GET lease and has rechecked shutdown, so a start-then-immediate-stop instance cannot take parked items and drop them. Alive ticks are not parked. If no successor starts, the parked call is not delivered (same class of loss as switching to the Delphi poller).

Acceptance: test_drop_returns_quickly_while_get_blocks asserts Drop returns in well under one second while a GET is parked. test_inflight_get_is_handed_to_successor and test_start_stop_start_third_instance_receives_parked_request cover rapid restart, including start then immediate stop then start. Watchdog reset must not freeze the VCL thread. Background join may still last up to the HTTP timeout.

WP7 — Establish wire compatibility and improve protocol security

Partial for compatibility (PKCS7 encrypt proven; dual unpad in the CAT install template). Remaining: deploy that PHP, pass or delete the Delphi IV. Versioned migration for AEAD. Addresses DWR-09 and DWR-10.

  • Done: OpenSSL PKCS7 golden vectors in dpwebrpc.rs. Live test-env poll decrypt and POST OK on 2026-08-15.
  • Done in git: gds/install/cat/webrpc_unpad.inc.php and input.php. webrpc_unpad on import_text — PKCS7 if valid (Rust), else rtrim NULs (Delphi). Do not use PKCS7-only openssl_decrypt; that rejects Delphi zero-pad. Isolation-deployed on the first test CAT host; fleet copy still needed. The gitignored gateway_server tree is not the source of truth.
  • Either pass the configured IV through the FFI or remove the misleading configurable Delphi property as part of a deliberate compatibility decision.
  • Design a versioned authenticated envelope for a later gateway migration, preferably with a unique nonce and AES-GCM or another reviewed AEAD.
  • Keep correct TLS mandatory even after the inner protocol gains authentication.

Acceptance: checked-in cross-implementation fixtures prove the current deployed wire contract, leftover pad is gone from the POST path, and old/new peers have an explicit version negotiation or rollout plan before further crypto changes ship.

WP8 — Redact logs and add operational telemetry

Open Addresses DWR-08 and DWR-13.

  • Replace plaintext payload logging with direction, sequence, action where safely extractable, byte count, duration, attempt, and correlation ID.
  • Never log passwords, session keys, authentication headers, encryption keys, cookies, or complete API responses.
  • Count poll attempts, valid empty polls, messages/batches received, malformed frames, decrypt failures, POST successes, retries, terminal failures, queue rejections, queue depth/high-water mark, oldest age, and shutdown duration.
  • Expose last successful valid poll and explicit poller/worker state to Delphi system status.
  • Review log file permissions, retention, rotation, and the effect of one oversized line.

Acceptance: normal and failure diagnosis is possible without payload logging, automated tests assert redaction, and production status distinguishes network, protocol, queue, delivery, and poller failures.

WP9 — Use monotonic time and production backoff

Open Addresses DWR-12.

  • Use Instant for elapsed time, deadlines, health age, and pacing.
  • Use capped exponential backoff with full jitter for repeated errors.
  • Reset backoff only after a valid successful exchange, not merely any HTTP 200.
  • Keep normal long-poll turnover prompt; do not add an unnecessary delay after a poll that already waited on the server.

Acceptance: forward/backward wall-clock changes do not alter retry deadlines, and a simulated fleet does not synchronize retries after an outage.

6. Rollout and Rollback

  1. Development: complete WP1–WP6 and cross-language fixtures. Keep use_rust_webrpc=false by default.
  2. Local live verification: run Rust against the actual local/test gateway with synthetic sessions. Exercise primary and secondary configuration, including an absent secondary.
  3. Fault campaign: inject DNS failure, invalid TLS, connection refusal, slow response, timeout after accept, malformed encrypted data, oversized response, gateway restart, queue pressure, and clock changes.
  4. Single-channel canary: enable Rust for one controlled gateway/channel while preserving the other channel or a fast settings rollback path.
  5. Limited production canary: monitor queue depth/age, delivery failures, poll health, reset duration, memory, thread count, request latency, and user-visible timeouts for an agreed period.
  6. Progressive rollout: expand only when every gate above has linked evidence and no unresolved blocker/high item.
Rollback: retain the existing use_rust_webrpc feature flag and Delphi implementation throughout the rollout. A rollback must safely stop and free the Rust instance before Delphi polling starts; this transition itself belongs in the lifecycle test matrix.
